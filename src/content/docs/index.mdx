## 認証 — 誰がログインできるか

DB に接続できる主体を制御し，なりすましや不正ログインのリスクを下げます。  
ローカルユーザーの認証強化（MFA）に加え，OCI IAM や Microsoft Entra ID などの外部 IdP と連携し，ユーザー管理を一元化する方式を扱います。

## アクセス制御 — 何が見え，何を操作できるか

正規のログイン後に，行・列・操作の単位でアクセスを絞ります。  
利用時のデータ（Data in Use）を守る層で，行・列レベルの絞り込み（VPD / OLS / Deep Data Security），特権ユーザーの抑止と職務分離（Database Vault），想定外の SQL の遮断（SQL Firewall）が含まれます。

  <LinkCard title="Virtual Private Database" description="Database 側で暗黙的に制御を行うことで，アプリの SQL を変えないままに行・列単位でユーザーごとに見えるデータを変えます。" href="./access-control/virtual-private-database/" />
  <LinkCard title="Database Vault" description="DBA などの特権ユーザーの操作も制限する強力なアクセス権限の分離を強制します。" href="./access-control/database-vault/" />
  <LinkCard title="SQL Firewall" description="許可済み SQL の特性から逸脱した SQL を検知・遮断し，SQLインジェクションを防止します。" href="./access-control/sql-firewall/" />
  <LinkCard title="Oracle Label Security" description="データとユーザーに付けたラベルの関係で，参照・更新の可否を判定します。" href="./access-control/oracle-label-security/" />
  <LinkCard title="Deep Data Security" description="26ai 新機能。エンドユーザーのコンテキストで行・列制御を DB 層に実装し，AI エージェントのアドホックなクエリにもアクセス制御を対応させます。" href="./access-control/deep-data-security/" />
</CardGrid>

## 暗号化・マスキング — データそのものを読めなくする

データを暗号化またはマスクし，経路や媒体を奪われても中身を読めなくします。  
保存データ（Data at Rest）は TDE，通信経路（Data in Transit）は NNE / TLS，クエリ結果は Data Redaction が担当します。

<CardGrid>

  <LinkCard title="通信暗号化" description="クライアント- DB 間の通信を暗号化。NNE（Oracle Net）と TLS（TCPS）の2方式を扱います。" href="./encryption/network/" />
  <LinkCard title="Data Redaction" description="クエリ結果を動的にマスクします。データ自体は書き換えず，参照時の見せ方だけを制御します。" href="./masking/data-redaction/" />
</CardGrid>
